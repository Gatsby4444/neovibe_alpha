## Difficultés / points de vigilance

- **JDK 17 hors PATH** : le `java` du PATH reste le JRE Java 8. Toute commande
  Gradle/build doit poser `JAVA_HOME=D:\jdk17` explicitement (comme sur
  l'ancienne machine avec `C:\Charles\dev\jdk17`).
- **Piège cross-disque `C:`↔`D:` (a fait échouer le 1er build APK)** : le cache
  Pub était par défaut sur `C:\Users\...\AppData\Local\Pub\Cache` alors que le
  projet est sur `D:`. Le compilateur **incrémental Kotlin** tente de calculer
  un chemin relatif entre la source d'un plugin (sur `C:`) et le build dir (sur
  `D:`) → `IllegalArgumentException: this and base files have different roots`
  sur les 5 plugins Kotlin (image_picker, url_launcher, video_player,
  shared_preferences, flutter_foreground_task). **Correctif appliqué** :
  `PUB_CACHE=D:\pub-cache` (posé aussi en variable utilisateur via `setx`),
  puis `flutter pub get` + `flutter clean` + rebuild. À garder : sur cette
  machine, le cache Pub DOIT rester sur le même disque que le projet.
- **Bug du compilateur incrémental Kotlin (a fait échouer le 2e build APK)** :
  après le correctif cross-disque, Gradle échouait encore avec « Could not close
  incremental caches … Daemon compilation failed » sur les 5 mêmes plugins
  Kotlin. **Correctif appliqué** : `kotlin.incremental=false` posé dans
  `C:\Users\USER\.gradle\gradle.properties` (config Gradle **machine**, hors
  repo) + `gradlew --stop` pour purger les daemons pollués. Le 3e build a
  réussi. Rebuilds un peu plus lents mais fiables. Le projet committé n'est
  pas touché.
- **Clé Supabase manquante** : l'app compile mais l'auth Supabase échouera à
  l'exécution tant que la vraie clé publishable n'est pas mise dans `env.dart`.
- **Compte de test dev perdu** (mémoire non rapatriée) : à recréer avec Jay.
